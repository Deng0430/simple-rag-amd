# 技术决策与评测边界

本页解释当前固定 RAG 原型的取舍。已有结果用于判断证据组织是否改善回答，尚未验证自主代理的规划能力。

## 为什么同时保留检索预览和模型问答

检索预览把资料交给使用者阅读，便于检查命中、原文与来源；模型问答让 Qwen 基于片段归纳答案。生成降低了自行组织信息的要求，也可能引入无依据解释，因而仍保留原文和 CSV。当前没有使用者阅读时间或纯检索对模型问答的独立质量实验，不给出量化增益。

## 候选方案与选择

| 决策 | 当前选择与依据 | 保留的替代方案或限制 |
| --- | --- | --- |
| 字面与语义检索 | TF-IDF 便于观察报错字面命中；BM25 保留中文与 API 关键词；E5 支持跨语言语义匹配 | 三种都可比较，分数不在同一尺度；并未证明 E5 对所有问题最好 |
| 嵌入模型 | multilingual-e5-small，CPU ONNX int8、384维向量，降低独立生成模型之外的运行负担 | M3 等方案提供更多表示方式，但未在本项目公平测量，不能按外部榜单直接宣布胜负 |
| 向量存储 | 当前716段冻结实验语料以NumPy矩阵和本地缓存处理，依赖及部署较简单 | 未进行大规模并发测试；资料量明显增加时再评估专用服务 |
| 生成后端 | 本地Ollama/Qwen2.5-3B量化适合现有设备；AUP保留ROCm PyTorch/Qwen3-4B路径 | 模型、量化、资料时期和设备不同，不能合并为硬件速度对照 |
| 全局证据补充 | 独立实验实现H融合与X扩展，保持原始输出、失败与分母 | 新12题Slot-F1未改善，因此没有据旧题局部收益替换网页默认方案 |

## 基线能回答的问题

第一轮 A 与第二轮 D 都是通用 Qwen2.5-3B 配常规 E5 Top-3。B/C 检查邻域扩展，H/X 检查融合与全局补充；模型未训练，问题、资料与协议固定。旧20题和新增12题分别报告。

该设计讨论“给同一生成模型怎样组织证据”。现有主表没有无检索通用模型组或计时的人工作答组，不能据此量化接入模型相对纯检索的收益。仅检索模式不生成短答案，也不宜用空答案给它计算EM来制造优势。后续补做对照时，应明确任务、回答格式、预算、允许获取的信息和评价方式，并另建运行版本。

## 为什么不只看一个分数

1. 首轮19/20题B/C的完整输入相同。输出分数不同不能证明未实际发生的输入干预有效。
2. 新12题X比D的Token-F1高3.96个百分点，但Slot-F1从16.00%降到13.79%；三组满足的必要槽位都是2个，错误补充增加。增加词面重合不等于操作条件更可靠。
3. 旧题X相对D的Slot-F1高9.31个百分点，但旧题已参与改进设计，不能替代未暴露题集。现有32题后续都应作为已暴露数据使用。

上述语义标签为AI辅助，人工复核未完成。已标注引文覆盖也不是穷尽的语义召回。结果保留异常、失败和格式截断，不能据重载模型的运行耗时给出加速或能耗结论。逐题记录及复算入口见 [公开实验材料](../experiments/README.md)。

## 与 Agentic RAG 的关系

Agentic RAG 关注检索过程中的动态决策。现有系统尚未实现模型驱动的查询改写、循环检索、工具执行或停止控制，H/X也按固定规则运行。基础模块及其失效分析为后续研究提供可复用接口，不能作为已完成代理能力评测的证据。

后续可以先研究有限动作的控制器：证据不足时继续检索，证据充分时回答，达到预算而仍不足时拒答。需要记录每步动作、选择依据、证据变化、请求数与token预算，并与固定流程比较。单纯增加代理名称、循环次数或更多上下文不构成有效改进。

相关方向可参考 [Agentic RAG综述](https://arxiv.org/abs/2501.09136v4) 与 [Self-RAG](https://proceedings.iclr.cc/paper_files/paper/2024/hash/25f7be9694d7b32d5cc670927b8091e1-Abstract-Conference.html)。Self-RAG包含特定训练与反思token机制，本项目未复现该训练；后续控制器的建议也不等同于其完整方法。
