# 技术文档 RAG：证据条件完整性实验记录

实验日期：2026-10-27，Asia/Shanghai。正式批次：`2026-10-27_test_v1`。记录的是**本地 Qwen2.5-3B 实验**，与历史 AMD AUP / Qwen3 云端部署和百科评测分开。

## 1. 实际结论

已执行 20 个任务的 A/B/C 三组实验，保存全部 60 个计划位置、61 次请求尝试及逐项评分。另完成 3 道开发题的 9 次生成，不计入正式结果。

**本轮没有获得足够证据证明“条件线索优先的邻域扩展”优于普通邻域扩展。** 虽然 B 的部分汇总分数较高，但 20 题中有 19 题的 B/C 完整输入相同，真正形成策略对照的仅 1 题。这一题两组都未答对关键条件。B/C 每题满足的必要槽位均相同，额外错误、格式失败和措辞变化解释了汇总分数的差异。

这是一份完成了运行与核查的小规模探索结果，不是得到方法有效性的阳性结果。它适合课程报告中的系统验证与失败分析：现有 demo 能执行检索、生成与记录，但文档检索、条件理解和结构化输出仍有明显限制。

## 3. 评价口径与正式结果

EM 与 Token-F1 评价结构化的 `short_answer`。分词使用逐汉字、连续英文/数字/下划线、其余非空白符号逐个词元；命令和路径保留大小写、标点及参数。它借鉴问答评测的 EM/F1，**不是英文 SQuAD 原版分数，也不是命令执行成功率**。格式失败、空回答及拒答保留分母，记零。

Slot-F1 为 `2TP/(2TP+FP+FN)`：对完整原始回答核查必要条件，正确满足记 TP，遗漏/错误条件记 FN，错误条件或不适用补充记 FP。正确的命令或路径可以直接体现条件，不强制复述题面。即使格式损坏，已生成的实质文本仍参与槽位核查。

槽位与建议判定是**隐藏组别的 AI 辅助初评，加协调复核**，尚无人类评分。每条回答由一名初评代理检查；不是三人独立重复评分。协调代理可以看到组别，因此不称为独立盲评。保留了初评、6 条协调变更及理由，并提供空白人工复核表。

## 4. 主比较与实验是否形成对照

B−C 的汇总差值为 EM **+5.00 个百分点**、Token-F1 **+6.85 个百分点**、Slot-F1 **+1.10 个百分点**。这些数字不能直接解释为策略收益：

- 19/20 题 B/C 完整提示逐字相同；其中 8 对原始输出仍不同。固定 seed 和 temperature=0 没有在本次服务中得到逐字一致的所有输出。原因未被隔离，不能将差异归给不存在的输入干预。
- 13/20 题没有同章邻域候选；7 题有扩展，其中 6 题两种排序最终选到同一批材料。
- 唯一不同输入是 `ce-14`：B/C 分别 1301/1287 输入 token，扩展 468/454 token，完整输入长度相差 1.08%。两组都错误允许 7 字符短 commit hash，必要槽位均为 FN。
- B/C 每题 TP、FN 都一样，逐题 Slot-F1 改善/恶化/持平为 **0/0/20**。Micro-F1 差异仅来自 `ce-14` 的 C 多说了一个错误缓存前提，FP 多 1；这不表示 B 补全了任何额外必要条件。
- EM 差异全部来自 `ce-08:C` 在相同输入下发生的 JSON 截断。Token-F1 的 4 道正向差异中，3 道也来自相同输入下的输出变化。

## 5. 检索与证据诊断

以冻结 gold 中已经标注的证据为准，共享种子的 Hit@3 为 **7/20=35.00%**，MRR@3 为 **0.300**。这不是完整 Recall：可能存在尚未标注的等价证据。

逐项检查槽位引用的原文是否完整出现在实际输入中，A 为 **7/20**，B/C 均为 **8/20**。增加的一题为 `ce-01`。这只叫“标注槽位引文覆盖率”，不是穷尽性的语义证据召回，也不代表出现引文后模型必然遵循。

当前同章±2扩展只能补近邻，不能自动跳到另一个章节的必要条件。AUP 用户指南的 47 个章节与 6 个项目说明章节在此切分中均为单段，没有同章候选。项目说明虽只有 6 段，也常进入 Top-3；本轮没有做其干扰程度的独立消融，不能把检索问题单独归因于它。

## 6. 代表性案例

**正确的操作回答：`ce-09:B/C` 离线安装。** 两组都生成了 `python -m pip install --no-index --find-links=/local/wheels -r requirements.txt`，同时禁止远程索引并指向给定 wheel 目录，EM=1、槽位 TP=1。A 在相同任务遇到两次空的不完整服务响应，最后记失败。B/C 相比 A 的这项差别不能当作扩展方法改善质量的证据。

**证据已检索到，但条件仍判断错误：`ce-05` 环境变量优先级。** 三组输入均含 `Used only when HF_HOME is not set!`，模型却回答显式设置 `HF_HOME` 后仍由 `XDG_CACHE_HOME` 决定 home 路径。三组都记 FP=1、FN=1。它展示的是对适用条件的误读，不能仅靠“加更多文档”解释或解决。

**格式失败掩盖正确内容：`ce-08:C`。** B/C 完整输入相同；C 已正确说出默认隔离环境不可见用户 site-packages，但引用列表循环重复，达到 512 token 后截断，JSON 无法解析。按预定规则 EM/F1=0，而原文条件槽位仍为 TP=1。B 的输出正常。结构化稳定性与语义条件正确性需要分别记录。

唯一形成 B/C 不同输入的 `ce-14` 也值得保留：两组都没有覆盖要求完整 commit hash 的标注引文，回答均错误许可短哈希。因此本轮不能用这个案例支持条件优先策略有效。

完成响应包含达到输出上限的截断响应。开销来自一次本地运行，受到加载、前缀缓存及运行时调度影响；没有做重复测量、能耗评测或跨硬件比较。峰值显存未测，环境快照不能冒充峰值。

59 条完成响应的服务输入 token 计数与固定 Qwen tokenizer 全部一致。最大输入为 1414，加预留输出为 1926，小于窗口 8192；实际最大扩展为 491，不超过 512。没有因输入超限而跳过任务。

`ce-09:A` 首次返回空 model、空 response、`done=false`，没有 token 用量，最初被检查器归为 tokenizer mismatch 后暂停。该响应没有证明计数不一致。保存原始记录后，将其识别为运行时不完整响应，按原协议仅重试一次，仍为空，最终保留失败。`runtime_recovery.json`、恢复脚本及 `predictions_before_runtime_recovery.jsonl` 保存了全部过程。未重跑语义错误、格式错误或截断输出，也未修改题目、gold、模型配置或组包规则。异常的服务根因仍未确认。

开发阶段为形成合法的组包对照，调整过 2 道开发题及统一的检索格式尾注清理规则，发生于正式生成前；未依正式结果换题。原开发题备份和冻结协议均已保留。当前 48 项单元测试通过；运行、评分所依赖的源文件和输入哈希核验通过。
