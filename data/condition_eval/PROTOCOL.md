# 条件与关键约束完整性：执行协议

日期：2026-10-27（Asia/Shanghai）。正式模型输出前冻结；具体文件版本以运行目录的 manifest 与 source_snapshot 为准。

- 目标 20 个不同操作任务，每题 A/B/C 三种上下文，共 60 个计划位置。问题和金标准由 AI 辅助依据官方原文构建，并经过来源交叉核对；没有独立人工标注。正式题不根据生成效果筛选。
- 测量的是**操作条件与关键约束完整性**，包括适用范围、先决条件、操作限制以及必要行为说明。所有槽位都记录 slot_type；整体 Slot-F1 不能解释成只测执行前提恢复。
- 固定 E5 小模型、同一语料、Top-3；查询统一去掉从“简短答案”起的输出格式要求，生成仍使用完整问题。该规则在开发阶段制定，不读取参考答案。
- 开发预检时，原三题的完整长问句没有形成B/C差异；去掉格式尾注后仍不足两题。为验证组包实现，在正式生成前将开发dev-01换为Python递归上限场景，dev-02改为git status格式稳定性比较，dev-03保留。原开发题保存在本机 `.cache/condition_eval/development_before_calibration.json`。调整只依据检索/组包属性，没有查看生成质量或改动正式20题；B/C规则及512预算未变。
- A 保留 Top-3 原文。B/C 共享同章前后各 2 个片段的候选池；B 优先含冻结条件词的片段，C 优先距离近的片段；扩展预算均为 512 token，按整个片段装入，不强行凑成等长。扩展呈现顺序按来源一致处理。
- 生成模型为本机已安装的 Ollama qwen2.5:3b / Q4_K_M，固定 digest，temperature=0、seed=42、num_ctx=8192、输出上限512。三组使用相同 JSON schema。
- 使用 Qwen 官方固定 revision 的 tokenizer，并将完整 ChatML 明确传给 Ollama `/api/generate` 的 `raw=true`，避免服务再次套入不透明模板。已在中英混合校验输入上与服务实际 token 计数比对；正式每条继续核对。该实验入口与网页 `/api/chat` 不同，不能将两种提示路径的历史耗时混合。
- 题目顺序及题内组别顺序按种子42随机化，串行运行，每条无历史对话。原始响应先保存；仅运行异常允许一次重试，语义错误/格式错误不重试。
- 计算短答案 EM 与 Token-F1；格式失败、无回答或拒答保留分母计零。保留大小写、命令参数及标点，按固定中文/英文/符号词元规则计算，不套用英文SQuAD的删标点规则。
- 槽位及关键错误由组别隐藏的 **AI 辅助核查**给出，保存逐项依据、TP/FP/FN、错误/可接受/拒答标签。它不是用户或人工标注，报告必须显示这一限制，并提供人工复核表。语义核查发现拒答冲突时另出覆核后的答案分数，自动原分数保留。
- 原语料中12个章节有长代码块分割，审计68处分割均在换行边界，无从单行中部强制切断。既有片段原样保留，不能假定每个多行示例片段独立可执行；金标准核对完整来源，模型输出不会被执行。
- 主要比较 B−C。报告全部20题，并单列B/C相同、无邻居、近似等长（完整输入差异≤5%且扩展不同）子集。相同输入不冒充有效策略差异；无改善也如实报告，不用测试结果调整规则后覆盖原实验。
- 计时仅是本机描述性记录；Ollama前缀缓存、加载和调度可影响延迟，不作严格加速或AMD平台优劣结论。未测显存峰值留空。

原始资料、输入、运行顺序、代码快照、金标准、全部尝试、预测、自动分数、辅助核查及环境保存在同一运行目录。结果与AMD AUP历史部署记录分开。辅助方法设计使用 experimental-design 工作流；工具方法来源见 https://doi.org/10.48550/arXiv.2609.00065 ，该引用不作为本方法有效性的证据。
