# 条件证据实验小型数据集 v1

本数据集于 2026-10-27 从项目已经缓存的官方文档构建，用于课程中的本地 Qwen2.5-3B 单轮 RAG 对照实验。它是 **AI 辅助构建并根据来源核对的标注草稿，尚未获得独立人工确认**，不能描述为人工专家标注基准。

## 文件与隔离

- `test_questions.json`：20 个正式任务，仅含 ID、场景、类别、问题和答案类型。
- `gold.json`：与问题 ID 对齐的评分参考，包括等价短答案、关键条件槽位、可接受补充、不适用建议和逐字来源引文。**仅供评分，不提供给检索、组包或生成过程。**
- `development.json`：3 道不同场景的开发题，包含参考标注，供输入组包与解析检查，不进入正式指标。生成时同样应剥离参考字段。

引用基于 `.cache/knowledge/corpus.json`，SHA-256：

本数据只引用官方文档片段，没有引用即将更新的项目说明。若重新抓取官方页面或更改片段正文，必须重新核对来源并更新数据版本。

## 覆盖与选题方式

四类各 5 题，共 20 个不同操作场景；每题标注 1 项关键条件，共 20 项。来源覆盖 10 份文档：Git clone、Hugging Face 下载与环境变量、pip 指南/通用选项/check、Python venv、Streamlit config、PyTorch HIP、VS Code Tasks。

| ID | 类别 | 场景 |
| --- | --- | --- |
| ce-01—ce-05 | 路径与工作目录 | Git 本地优化的地址写法、Streamlit 工作目录配置、下载缓存文件不可原地修改、venv 搬迁、缓存环境变量优先级 |
| ce-06—ce-10 | Python 与依赖环境 | pip 检查、按需升级、隔离环境用户安装、离线 wheel、隔离配置 |
| ce-11—ce-15 | 版本与设备条件 | ROCm TF32、CK SDPA 构建、venv setuptools 版本变化、模型下载 revision、浅克隆分支 |
| ce-16—ce-20 | 网页服务与运行配置 | VS Code 后台依赖、Streamlit 监视路径、Hub 离线模式、pip 虚拟环境限制、Hub 令牌优先级 |

选题先按上述覆盖目标和来源可回答性确定，没有查看生成模型的正式答案、A/B/C 组效果或检索是否命中。无同章邻居和基线已经含条件的任务应保留，不按预计提升筛选。

既有 `aup-q01`—`aup-q06`（Python 命令缺失、ensurepip、网页代理、会话保存、AMD cuda 接口、CPU/GPU 资源选择）及其同场景改写没有进入本测试集。开发题经检索/组包校准后分别是 Python 递归限制、Git status 脚本格式稳定性、pip 上传时间筛选元数据，与正式场景不同。

## 标注规则与限制

- 根据完整回答与问题已经给定的场景共同判断。**正确命令、参数或路径已经体现条件时可计为满足，不强制复述题目中的操作系统、目录或环境。** 例如 `/work/.streamlit/config.toml` 已体现工作目录条件。
- `acceptable` 是语义等价表达的示例，不是必须出现的关键词列表。不要用简单 substring 匹配冒充完整槽位评分。
- 本集测量“操作条件与关键约束完整性”。`slot_type` 区分 `prerequisite`（先决条件）、`applicability`（适用范围）、`operational_constraint`（操作约束）和 `behavior_explanation`（行为说明）。行为说明不冒充纯执行前提；后续应可按类型检查结果。
- 已给定的 wheel 齐备、当前使用 ROCm 等背景不单独要求重复陈述。涉及明确版本起点、缺缓存后的行为、错误退出码等未直接给出的关键约束，仍须按答案实际内容核对。
- `reference_answers` 用于 EM/Token-F1；有限字符串无法穷尽语义等价说法。命令和 Linux 路径的大小写、斜杠、引号、参数及连接符应保留。短答案的文字匹配分数不能代替操作正确性。
- 部分题通过选择正确选项即可满足关键条件，这会带来较容易的题和天花板效应。本集只是一份文档技术问答小样本，不代表复杂多跳任务，也不能据此估计真实学生问题分布中的错误率。
- 没有运行参考命令。来源中的长代码被切分时，使用独立完整的句子或操作示例核对，不能将片段中的半截代码解释为完整可执行命令。
- 所有 `relevant_evidence.quote` 已检查为对应官方片段正文的逐字子串，所有槽位的证据 ID 均在对应任务引用中。若后续发现标注错误，必须记录修订理由并对各组统一重评。
- 冻结前经过另一代理独立核查引用与问题措辞，并修正 ce-05 的变量优先级措辞、ce-06 的解释器场景、ce-09 的路径前提与等价命令；ce-01/ce-03 改为真实条件/操作约束而不是功能描述。这些调整均发生在未读取正式预测的阶段。
- 开发阶段为验证 B/C 确实能产生不同输入，依据仅检索/组包结果调整了 dev-01 和 dev-02；未查看生成答案。开发集原版保存在 `.cache/condition_eval/development_before_calibration.json`。dev-03、20 道正式题及其 gold 均未因此改变；后续报告应披露这一开发校准过程。
- 题目、gold 与开发集尚须在正式生成前共同冻结版本。AI 辅助核对的结论和之后的模型辅助评分必须明确标注，不能伪称用户已亲自人工评审。

第三方文档保留原许可。这里仅保留核对所需的少量引文和原始链接；完整缓存正文与模型权重不随本目录发布。
